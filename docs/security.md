# Security boundaries

Source files, comments, patches, transcripts and model responses are untrusted data. wy never imports application modules, executes source, runs transcript commands, or runs tests merely to analyze a repository. Git commands use argument arrays; imported revisions are resolved with `--end-of-options`. Diff application and external diff/textconv programs are not used.

Repository enumeration uses Git's tracked and non-ignored untracked files, a text-extension allowlist, a 512 KB per-file limit and a 12 MB context budget. Credential-like filenames, `.env` variants, Git internals, `.wy`, `.codex`, `.claude`, dependencies, generated build directories, binary files and symlinks are excluded. Transcript discovery retains only metadata and matches the recorded working directory to the current Git root. Codex metadata is read from the first record; Claude metadata is found in a bounded prefix (up to 100 lines / 1 MB), which may contain message bodies that discovery does not retain. Unrelated or missing workspace metadata is excluded, including for explicitly selected transcripts. A workspace recorded in a transcript is an association, not authenticated authorship. Ingestion is capped at 20 MB per transcript and 20 sessions / 40 MB per review, retains bounded observable event text, and omits private reasoning and system records. Claude thinking and redacted-thinking blocks are excluded. Session evidence is namespaced by provider and session; stored snapshots are referenced independently by each review.

Common API tokens, password/token assignments, bearer tokens, private key blocks and credential-bearing URLs are redacted before persistence and model input. Private-key redaction preserves line counts. Hashes refer to the original source bytes, so redaction does not make unsafe anchors appear current. Redaction cannot identify every custom credential or sensitive business value. Do not treat it as a data-loss-prevention guarantee.

Compaction summaries are secondary evidence. Original links require explicit identities, repository-scoped captures and verified direct parent boundaries when crossing sessions. Complete retained public messages can be preserved as originals; analysis, encrypted content and generated replacement history are not promoted to original speech. Known opaque compaction markers produce a fixed placeholder without importing private/system text. Source links pin a saved snapshot and captured-content hash rather than opening raw transcript files. Missing, ambiguous or over-budget references are displayed as unavailable. These checks preserve provenance; they do not authenticate provider metadata or establish semantic support for a summary claim.

Browsing, review, and the legacy standalone offline investigation make no network requests. Explicit `wy reason`, terminal **Explain changes**, `/reason`, and terminal `/ask` send a bounded, redacted evidence packet to the installed Codex or Claude CLI using its existing authentication and account usage. The packet contains actual diffs, source context and repository-scoped observable history (up to 100,000 evidence characters / 80 items). These processes run in a temporary directory with modification tools, hooks, plugins and external tool integrations disabled; they do not resume or alter the original coding session. Cancellation and a timeout stop the subprocess. Structured responses must cite supplied evidence IDs, and repository changes during generation are recorded as snapshot-staleness warnings. Explanations are separate retrospective assessments, never promoted to recorded intent.

The older direct model-provider option requires `--model` and an explicitly named `WY_MODEL`. Non-loopback endpoints additionally require `WY_ALLOW_REMOTE=1` and HTTPS. Only process environment configuration is read: a repository cannot opt itself into external processing. HTTP redirects and environment proxies are disabled. Endpoint credentials in URLs are rejected. Optional bearer credentials come from `WY_PROVIDER_API_KEY` and are not persisted. Model prompts treat all supplied content as evidence, not instructions. Structured output and citation checks restrict effects, but cannot guarantee resistance to every semantic prompt injection.

SQLite and atomic JSON artifacts are created with private file modes under a private `.wy` directory. Symlinked storage and database locations are refused. Do not commit `.wy`: it contains redacted source snapshots, transcript excerpts, absolute local paths and potentially sensitive context that redaction did not recognize. This is not encrypted storage or a multi-user adversarial sandbox. Previously created file modes, concurrent filesystem replacement attacks and malicious local processes are outside the MVP threat model.

The extension requires a trusted workspace, validates cache structure and paths, checks snapshots before showing annotations, and escapes all dynamic HTML. Its webview uses a restrictive nonce-based CSP, has no external resources, and navigates only to validated source evidence inside the workspace. Transcript evidence is shown as the saved redacted excerpt rather than opening the raw potentially sensitive transcript. CLI executable configuration is machine-scoped; subprocesses use argument arrays with no shell. The extension does not execute code while displaying cached annotations.
